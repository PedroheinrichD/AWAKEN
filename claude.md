# CLAUDE.md — AWAKEN — Real Life RPG

## 1. Visão do projeto

**AWAKEN — Real Life RPG** é um RPG de evolução pessoal inspirado na sensação de progressão, descoberta, perigo e poder de obras como Solo Leveling.

O objetivo é transformar atividades físicas reais em um sistema de RPG completo.

O jogador não deve sentir que está usando um aplicativo de academia com elementos de RPG.

Deve sentir que está **vivendo a evolução de um personagem**.

O projeto é inicialmente privado para apenas **dois jogadores**, que podem estar em cidades diferentes.

### Princípio central

> A vida real é o campo de batalha.
> O exercício é o combate.
> A evolução física é a evolução do personagem.

---

# 2. Filosofia do jogo

O sistema deve priorizar:

* descoberta;
* progressão;
* risco;
* recompensa;
* raridade;
* eventos inesperados;
* sensação de poder;
* competição;
* consequências;
* estratégia;
* evolução não linear;
* conteúdo secreto;
* momentos memoráveis.

Evitar transformar o jogo em:

* checklist de academia;
* contador simples de exercícios;
* sistema de “faça 100 repetições para ganhar XP”;
* progressão puramente numérica;
* árvore de habilidades previsível;
* jogo onde o jogador sabe antecipadamente tudo que poderá desbloquear.

---

# 3. Progressão

## Nível

O personagem possui nível de **1 a 1000**.

A progressão não deve ser linear.

Quanto maior o nível, mais difícil deve ser evoluir.

Subir de nível no início deve ser relativamente acessível.

Subir de nível nos estágios avançados deve exigir muito mais esforço.

O sistema deve evitar progressão baseada simplesmente em aumentar absurdamente a quantidade de repetições.

Exemplo do que NÃO fazer:

> Rank B = 200 flexões.

A dificuldade deve evoluir principalmente através de:

* novas variações;
* maior complexidade;
* desafios combinados;
* tempo;
* execução;
* condições específicas;
* resistência;
* desafios especiais;
* bosses;
* eventos;
* missões;
* conquistas.

---

# 4. Ranks

Os ranks são independentes do nível.

Hierarquia:

**E → D → C → B → A → S → S++**

Alcançar determinado nível não promove automaticamente o personagem.

O nível apenas pode liberar a possibilidade de tentar uma promoção.

Uma promoção pode exigir:

* nível mínimo;
* atributos mínimos;
* conquistas;
* missões;
* sequência de desafios;
* Boss específico;
* condições especiais;
* desafio de promoção.

A promoção deve parecer uma conquista importante.

---

# 5. Exercícios

Exercícios principais:

* flexões;
* agachamentos;
* abdominais;
* corrida.

Também existem exercícios avançados de calistenia.

Exemplo:

### Rank E

Flexão normal.

### Rank D

Flexão declinada.

### Rank C

Flexão diamante.

Ranks superiores devem introduzir variações progressivamente mais difíceis.

A mesma filosofia deve ser aplicada a:

* agachamentos;
* abdominais;
* corrida;
* calistenia.

A dificuldade não deve ser criada apenas aumentando a quantidade.

# 10. Morte

A morte é uma mecânica central.

Se o HP chegar a zero:

> **O personagem morre.**

Ao morrer, o jogador perde literalmente tudo relacionado ao personagem:

* nível;
* XP;
* rank;
* atributos;
* equipamentos;
* armas;
* armaduras;
* inventário;
* itens;
* recursos;
* progresso;
* evolução da jornada.

Depois disso, deve criar um novo personagem.

A morte deve possuir peso real.

## Exceção absoluta

**X1 nunca pode causar morte permanente.**

Uma derrota no X1 não pode destruir o personagem.

---

# 11. Ressurreição

Devem existir formas extremamente raras de recuperar um personagem morto.

A ressurreição deve ser difícil.

Não deve funcionar como um simples botão.

Podem existir:

### Poção de Ressurreição Coletiva

Pode ser utilizada para ressuscitar um companheiro durante determinados eventos ou Bosses coletivos.

### Item de Ressurreição Solo

Item extremamente raro capaz de ressuscitar o próprio personagem.

A existência desses itens não deve remover o peso da morte.

# 12. Habilidades

Habilidades são independentes dos equipamentos.

Um personagem possui habilidades próprias.

Elas podem ser utilizadas durante Bosses, eventos e determinadas situações de combate.

Exemplos de efeitos:

* aumento temporário de força;
* aumento de dano;
* esquiva;
* crítico;
* regeneração;
* redução de dano;
* aumento de stamina;
* alteração de desafios;
* invocação;
* controle de Boss;
* efeitos especiais;
* habilidades relacionadas a determinados exercícios.

As habilidades devem possuir características como:

* nível da habilidade;
* custo;
* cooldown;
* duração;
* efeito;
* requisitos;
* condições de uso.

---

# 13. REGRA FUNDAMENTAL — HABILIDADES SECRETAS

## O jogador NÃO pode visualizar habilidades futuras.

Esta é uma regra obrigatória.

Não criar:

* árvore de habilidades;
* lista de habilidades bloqueadas;
* habilidades futuras com cadeado;
* nomes de habilidades futuras;
* requisitos futuros;
* nível necessário para habilidades futuras;
* porcentagem de progresso;
* silhuetas;
* previews;
* “próxima habilidade”;
* lista de habilidades dos próximos ranks.

Se uma habilidade ainda não foi descoberta, **ela não deve aparecer para o jogador**.

O jogador deve descobrir as habilidades através da própria jornada.

---

# 14. Sistema de DESPERTAR

Algumas habilidades devem ser despertadas através de condições específicas.

Exemplo:

O jogador pode estar no nível 300 sem sequer saber que existe determinada habilidade.

Após cumprir uma condição secreta:

> **DESPERTAR**

Uma nova habilidade é revelada.

Somente nesse momento o jogador conhece:

* nome;
* descrição;
* efeito;
* funcionamento;
* requisitos que já foram cumpridos;
* condições necessárias para utilização.

Algumas habilidades podem possuir condições de descoberta extremamente específicas.

Exemplo conceitual:

* derrotar determinado Boss;
* possuir determinado título;
* sobreviver com HP crítico;
* completar determinada sequência;
* executar uma ação inesperada;
* derrotar um Boss de determinada maneira;
* possuir determinado item;
* cumprir uma combinação de eventos.

O jogador não deve saber antecipadamente que essas condições existem.

---

# 15. Habilidades absurdamente raras

O jogo deve possuir habilidades de alto nível que sejam realmente extraordinárias.

Elas não devem ser apenas:

> +20% de força.

Devem alterar a maneira como o jogador joga.

Exemplos conceituais:

## ERGA-SE

Inspirada no conceito de levantar os Bosses derrotados.

Após derrotar determinado Boss, o jogador pode ter a possibilidade de transformá-lo em uma entidade subordinada.

O Boss derrotado passa a fazer parte do exército do jogador.

Pode posteriormente ser convocado contra outro Boss.

O Boss subordinado pode:

* causar dano;
* utilizar sua habilidade;
* aplicar efeitos;
* auxiliar em determinadas situações.

Bosses mais poderosos devem ser muito mais difíceis de transformar em subordinados.

---

## EXÉRCITO

Uma evolução extremamente rara de habilidades relacionadas à invocação.

Permite manter vários Bosses derrotados como subordinados.

Cada subordinado pode possuir função diferente.

Exemplos:

* dano;
* defesa;
* regeneração;
* debuff;
* suporte;
* habilidade especial.

O jogador escolhe quais subordinados utilizar.

---

## MONARCA

Habilidade extremamente avançada.

Pode criar um estado temporário de poder excepcional.

Pode alterar determinadas regras do combate durante alguns turnos.

Deve possuir requisitos absurdamente difíceis.

---

## DEVORADOR

Permite absorver características específicas de determinados Bosses derrotados.

Não deve simplesmente copiar o Boss.

Pode gerar efeitos únicos.

---

## ÚLTIMO SUSPIRO

Quando o personagem sofreria uma morte, pode impedir a morte em condições extremamente específicas.

Pode deixar o personagem em estado crítico e conceder uma oportunidade extraordinária de sobrevivência.

Deve possuir cooldown ou condição extremamente restritiva.

---

## SOBERANO

Uma habilidade de endgame extremamente rara.

Pode permitir combinações de habilidades normalmente incompatíveis.

Deve representar um dos maiores níveis de poder disponíveis.

# 19. Bosses

Cada Boss pode possuir:

* nome;
* rank;

* dano;
* habilidades;

**E → D → C → B → A → S → S++**

Bosses superiores devem possuir:

* combinações;
* condições;

# 20. Bosses aleatórios

Bosses podem surgir aleatoriamente.

Um dia pode aparecer um Boss E.

Outro dia pode aparecer um Boss B.

Em ocasiões extremamente raras pode aparecer um Boss S ou S++.

Isso deve gerar expectativa e imprevisibilidade.

---

# 21. Combate contra Boss — sistema de turnos

Boss fights são combates por turnos.

Não são apenas uma missão única.

Exemplo:

> **Turno 1**
>
> 50 agachamentos
> Tempo limite determinado.

Os jogadores realizam o desafio.

Depois o sistema resolve o turno.

O Boss pode:

* não atacar;
* atacar um jogador;
* atacar os dois;
* causar dano normal;
* causar dano crítico;
* utilizar habilidade;
* utilizar item;
* aplicar condição;
* modificar o próximo turno.

---

# 22. Desempenho durante o turno

O desempenho dos jogadores influencia o resultado.

Exemplo:

### Desempenho ruim

Maior probabilidade de sofrer ataque.

### Desempenho normal

Probabilidade normal.

### Desempenho excelente

Maior chance de evitar ataque ou gerar vantagem.

### Desempenho excepcional

Pode gerar eventos especiais, dano adicional ou outros efeitos.

O sistema deve evitar que o resultado seja completamente previsível.

---

# 23. Bosses também possuem estratégia

O Boss não deve simplesmente executar um ataque aleatório.

Bosses podem:

* escolher ataques;
* usar habilidades;
* utilizar itens;
* recuperar HP;
* aplicar debuffs;
* alterar desafios;
* preparar ataques;
* reagir ao desempenho dos jogadores.

Bosses superiores devem possuir comportamento mais complexo.

---

# 24. Habilidades e itens de Boss

Exemplos:

### Selo Arcano

Bloqueia o uso de itens pelo jogador durante um turno.

### Maldição da Duplicação

Duplica o próximo desafio.

Exemplo:

> 30 agachamentos → 60 agachamentos.

### Barreira Sombria

Reduz o dano recebido pelo Boss durante um turno.

### Dreno

Recupera parte do HP do Boss.

### Golpe Devastador

Ataque de dano elevado sob determinadas condições.

Bosses podem possuir habilidades exclusivas.

---

# 25. Loot

O rank do Boss determina o teto de raridade dos itens que podem ser obtidos.

O loot possui aleatoriedade.

O jogador pode derrotar um Boss sem receber um item.

Quando recebe um item, sua raridade deve ser determinada por probabilidades.

Conceito de progressão:

* Boss E → itens de baixa raridade;
* Boss D → itens comuns/incomuns;
* Boss C → possibilidade de raros;
* Boss B → possibilidade de raros superiores;
* Boss A → possibilidade de itens extremamente raros;
* Boss S → itens de altíssima raridade;
* Boss S++ → possibilidade de itens extraordinários, incluindo DEUS.

As probabilidades exatas devem ser balanceadas posteriormente.

A regra principal é:

> **Boss mais poderoso = maior teto de recompensa e possibilidade de itens absurdamente raros.**

# 30. Loja de Eventos

Deve existir uma **Loja de Eventos** separada do loot normal.

A loja recebe itens provenientes de eventos.

O jogador pode obter uma moeda/event currency através de:

* eventos;
* Bosses;
* missões especiais;
* desafios;
* conquistas;
* recompensas especiais.

Essa moeda pode ser utilizada para comprar itens na Loja de Eventos.

A loja pode possuir rotação.

Alguns itens podem ser:

> **EXCLUSIVOS DE EVENTO**

Esses itens não precisam estar disponíveis através de Boss loot normal.

Isso cria diferentes formas de aquisição:

**Boss → drop aleatório**

**Evento → recompensa**

**Evento → moeda**

**Loja de Eventos → item exclusivo**

**Missão/Conquista → recompensa especial**

# 36. Regra de design para recompensas

Quanto mais extraordinária a recompensa, mais extraordinária deve ser sua obtenção.

Uma habilidade ou item capaz de alterar drasticamente o jogo deve exigir algo proporcionalmente difícil.

Evitar:

> nível alto = automaticamente recebe poder absurdo.

Preferir:

> nível alto + condição rara + desafio difícil + descoberta inesperada = poder extraordinário.

---

# 37. Sensação de progressão

O jogador deve perceber evolução em múltiplas dimensões:

* físico;
* nível;
* rank;
* atributos;
* habilidades;
* equipamentos;
* títulos;
* conquistas;
* Bosses derrotados;
* eventos;
* coleção;
* reputação;
* histórico.

Não transformar toda evolução em XP.

---

# 38. Princípio de raridade

Itens, habilidades, Bosses e eventos extremamente raros devem realmente parecer raros.

Se algo é chamado de:

* Ultra Raro;
* Lendário;
* DEUS;
* habilidade secreta;
* despertar;

isso precisa ter peso.

Não distribuir conteúdo de alto nível com facilidade.

---

# 39. Princípio de surpresa

O jogador deve ser capaz de entrar no jogo sem saber exatamente o que poderá encontrar naquele dia.

Pode acontecer:

> “Um Boss apareceu.”

Ou:

> “Um portal foi encontrado.”

Ou:

> “Uma nova habilidade foi despertada.”

Ou:

> “Você encontrou um item que nunca tinha visto.”

Ou:

> “Uma condição secreta foi cumprida.”

Essa imprevisibilidade é parte essencial do jogo.

---

# 40. Princípio de longo prazo

O sistema deve ser projetado para durar muito tempo.

O jogador deve sempre ter motivos para continuar:

* subir de nível;
* melhorar rank;
* encontrar itens;
* descobrir habilidades;
* derrotar Bosses;
* participar de eventos;
* completar conquistas;
* aumentar streak;
* competir no X1;
* descobrir conteúdo secreto;
* buscar itens DEUS;
* descobrir novas formas de evolução.

---

# 41. Regra final

AWAKEN não deve parecer uma lista de exercícios com uma interface bonita.

Deve parecer um **RPG vivo aplicado à vida real**.

O jogador deve sentir:

> **“Eu estou evoluindo.”**

> **“Existe algo que eu ainda não descobri.”**

> **“Posso perder tudo.”**

> **“Posso encontrar algo extremamente raro.”**

> **“Meu personagem está ficando mais forte.”**

> **“Eu não sei o que vai acontecer amanhã.”**

A sensação de **descoberta, risco, poder e evolução** deve guiar todas as decisões de design.
